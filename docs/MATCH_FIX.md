# 경기 엔진 정합성 수정 기록

## 1. 원인 분석 (수정 전 코드 기준)

수정 전 `js/engine/match.js`는 **"이벤트를 확률로 먼저 뽑고, 위치는 그림용으로 나중에 만든다"** 구조였다.
보고된 증상은 모두 이 구조에서 나온다.

| 증상 | 원인 (수정 전 코드) |
|---|---|
| 주요 장면 카드와 미니맵이 안 맞음 | `planScenes()`가 시간만 정해 두고, 장면 시점에 `buildScene()`이 시나리오를 무작위로 골랐다. 장면 내용은 선수 위치를 전혀 보지 않았고, 효과(`applyEffects`)는 `killPlayer`, `takeObjective`, `takeStructure`를 **위치 확인 없이** 즉시 호출했다. |
| 바론 싸움인데 선수들이 미드를 왔다갔다 함 | `positions()`가 매 틱 새 목표 좌표를 만들었다. 교전 위치(`fightLoc`)는 오브젝트가 있으면 둥지, 없으면 **맵 중앙 ±0.15 무작위**였다. 킬에 관여하지 않은 선수는 `group`(미드 라인 위 점)으로 보내졌고, 같은 틱에도 70% 확률로 오브젝트 쪽과 미드 쪽이 바뀌어 왔다갔다 했다. |
| 운영 없이 5명이 미드에만 서 있음 | 14분(`laningEnd`) 이후 `positions()`는 스플릿 성향이 높은 탑 1명만 빼고 **전원을 `group` 한 점**(미드 라인)에 세웠다. 팀 계획 개념이 없었다. |
| 유충·전령을 10초 만에 처치, 위치는 상대 정글 | `objectivePhase()`가 틱(10초)마다 `takeChance × urgency` 확률로 **그 틱에 바로** `takeObjective()`를 호출했다. 처치 시간이라는 개념이 없었고, 처치 팀이 둥지에 있는지도 확인하지 않았다. 정글러 위치는 `campPos()` 순환이라 상대 정글에 있을 수 있었다. |
| 넥서스 쪽으로 가지도 않았는데 게임 종료 | `push()`가 "예산" 개수만큼 `takeStructure()`를 연달아 호출해, 한 틱 안에 포탑·억제기·쌍둥이 포탑·넥서스를 **원거리에서** 부술 수 있었다. 미니맵 위치와 전혀 무관했다. `applyEffects`의 `win` 효과는 쌍둥이 포탑을 0으로 만들고 바로 넥서스를 파괴했다. |
| "한타"인데 1명만 죽음 | `teamfight()`는 이벤트 이름을 늘 `teamfight`로 붙였고, 참여 인원은 "살아 있는 전원(스플릿 탑 일부 제외)"이었다. 사상자 수는 `0.14 + 0.26×rand + 0.25×우세도` 공식이라 1명만 죽는 경우가 흔했다. 위치·거리 개념이 없어 "근처에 없는 선수"도 참여했다. |
| 죽은 선수가 미니맵에서 움직임 | 사망 즉시 `placeAtFountain()`으로 우물에 순간이동했다. |

요약하면 **위치(미니맵)와 결과(이벤트) 사이에 인과관계가 없었다.** 위치는 이벤트를 꾸미는 장식이었고,
화면(`matchScreen.js`)도 미니언 위치·교전 위치를 따로 계산해 그렸다.

## 2. 새 구조

```
매 tick (5초)
 1) 부활·오브젝트 등장·수입
 2) 팀 운영 AI(teamai.js)가 팀 계획을 정함      ← 상태 머신
 3) 선수마다 계획에 따른 목표 지점·행동을 받음
 4) 귀환/텔레포트 채널링 처리 (완료 시 순간이동 + 로그)
 5) 이동: 속도 제한 안에서 목표 쪽으로 실제 이동
 6) 판정: 실제로 가까이 있는 선수들 사이에서만
      - 교전(combat.js): 거리 기반 클러스터 → 교전 개시 → 1초 단위 피해 계산 → 사망/도주
      - 오브젝트(world.js): 둥지 안 인원·골드로 처치 시간 계산, 진행도 누적
      - 포탑·억제기·넥서스(world.js): 근처 챔피언/미니언 웨이브만 피해, 순서 강제
 7) 상점(우물에서만), 체력 회복, 장면 판정
```

- 맵 데이터: `data/map.js` (0~1 좌표). 기하 함수: `js/engine/mapgeo.js`.
- 미니맵·문자중계·장면 카드·HUD는 모두 엔진 상태(`p.x, p.y, p.alive, p.task, g.waves, g.obj, 구조물 hp`)와 이벤트(`ev.pos, ev.parts`)만 읽는다.
- 문자중계 문장 선택은 `js/engine/commentary.js`로 옮겨, 검사기도 같은 함수를 쓴다.
- 주요 장면은 `js/engine/choices.js`가 **실제 상황(내 위치, 근처 적·아군, 근처 오브젝트)**에서만 만든다. 효과는 근처 선수에게만 적용하고, 오브젝트·포탑 효과는 "즉시 획득"이 아니라 **팀 계획 변경 + 보정**으로 바뀌어 엔진이 실제로 이동·처치한다.

## 3. 구현 요약

| 요구 | 구현 위치 |
|---|---|
| 맵 좌표·지역 | `data/map.js` (기지·우물·넥서스·쌍둥이 포탑·억제기·라인 포탑·라인 경로·강·정글 캠프·둥지·시야 지점), `js/engine/mapgeo.js` (`regionOf`, 라인 투영) |
| 이동 속도 | `CONFIG.match.sim.moveSpeed` 0.0275/초 → 맵 대각선 1.30을 약 47초. 순간이동은 귀환(8초 채널링 → 우물), 텔레포트(4초, 아군 포탑·와드·미니언만), 부활(우물)뿐이며 모두 `move` 이벤트로 기록 |
| 사망자 | 죽은 자리에 그대로 멈춤, 모든 판정에서 제외 |
| 팀 운영 AI | `js/engine/teamai.js`: 계획(라인전·미드 그룹+사이드·1-3-1·오브젝트 준비/처치/견제·공성·수비·끊기·넥서스 공성·전령 사용·반대편 교환) + 개인 임무(정글 동선·갱킹·귀환·후퇴·텔레포트). 상대가 처치를 시작하면 한 번만 견제 여부를 굴리고, 견제하지 않으면 반대편 포탑과 교환 |
| 오브젝트 | `world.js objectives()`: 처치하러 온 팀이 둥지 안에 있어야 시작, 인원·골드로 필요 시간 계산(`sim.objTime`), 둥지가 비면 진행도 초기화, 둥지 안 교전 중에는 멈춤, 끝날 때 상대 정글이 둥지에 있으면 스틸 판정 |
| 전령 | 소환 지점 → 라인을 따라 실제로 이동 → 포탑 도착 시 피해. 수비 챔피언이 근처에 있으면 전령 체력 감소 |
| 교전 | `combat.js`: 0.07 거리로 무리를 묶고, 적과 0.065 안이면 상황별 확률로 교전 개시 → 1초 단위 피해(파워·레벨·골드·조합·버프·포탑) → 체력·전력비로 도주 → 추격 판정. 이름: 각 4명 이상 = 한타, 1대1 = 솔로킬, 한쪽 1명 = 끊기/갱킹, 그 외 소규모 교전 |
| 포탑·넥서스 | `world.js structures()`: 바깥부터 순서대로, 사거리 안 챔피언·미니언 웨이브만 피해. 미니언 없이 들어가면 포탑이 챔피언을 공격. 넥서스는 쌍둥이 포탑 2개 + 억제기 1개 이상 파괴 + 상대 기지 안 3명 이상일 때만, 그 선수들이 직접 쳐서 파괴 |
| 문자중계 | `commentary.js describe()` → 화면과 검사기가 같은 함수 사용. 위치·오브젝트 단어는 `ev.lane / ev.region / ev.obj`에서만 채움 |
| 주요 장면 | `choices.js buildScene()`: 장면 위치 = 내 위치, 참여자 = 반경 안 실제 선수 전원, 카드 = 그 틱 엔진 체력·궁·점멸·레벨. 설명 속 사실은 `data/sceneNeeds.js` 조건으로 확인(숫자는 엔진 값). 효과는 근처 선수에게만, 오브젝트·포탑 효과는 "팀 계획 변경 + 보정"으로 엔진이 실제로 이동·처치. 다른 곳에서 벌어지는 일을 다루는 장면 5개(mid_roam, mid_tp_save, top_tp, top_backline_tp, sup_roam)는 장면 위치와 내 위치가 어긋나 쓰지 않음 |
| 미니맵 | `matchScreen.js`: 선수 좌표·웨이브(`g.waves`)·전령·와드·처치 게이지를 엔진에서 그대로 그림. 장면 때 작아진 미니맵에 장면 위치 깜빡이는 원 + 관련 선수 강조 |
| 디버그 | 설정 → 디버그 모드: 선수별 임무, 목표 화살표, 팀 계획, 오브젝트 처치 게이지 |
| 버그 신고 | 경기 화면 🐞 버튼 → JSON(입력·시드·선택·최근 30초) → `node tools/replay-bug.mjs` 로 같은 장면 재현 + 검사 + 타임라인 |

## 4. 검사기

`node tools/validate-match.mjs [판 수=500]` (검사 로직은 `tools/lib/match-checker.mjs`, 재현기와 공유)

1. 이벤트 참여자가 이벤트 위치 근처 (킬: 0.17, 교전: 교전 기간 중 교전 반경, 구조물: 포탑 사거리, 오브젝트: 둥지)
2. 한 틱 이동 ≤ 속도 한도 (귀환·텔레포트·부활은 `move` 로그 + 채널링 시간 + 목적지 검사)
3. 죽은 선수는 움직이지 않고 이벤트에 참여하지 않음
4. 오브젝트는 등장 후 시작, 최소 처치 시간 동안 처치 팀이 둥지에 연속으로 있었음
5. 포탑 순서, 넥서스 조건(쌍둥이 포탑·억제기·기지 안 3명·넥서스 앞 공격자), 시간 초과 종료 금지
6. "한타"는 양 팀 각 4명 이상일 때만 (반대로 4대4 이상을 다른 이름으로 부르는 것도 위반)
7. 0~14분 5명이 미드 라인에 함께 있는 시간 < 10%
8. 14분 이후 한쪽 팀이라도 사이드 라인에 1명 이상 있는 시간 ≥ 35%
9. 장면 위치·참여자·카드 수치가 같은 틱 엔진 상태와 일치, 반경 안 선수 누락 없음, 설명에 빈 변수 없음
10. 문자중계 문장(이벤트마다 쓰일 수 있는 문장 전부)의 위치·오브젝트 단어가 이벤트 데이터와 일치

- 증상: 라인전 중 내 탑 선수가 1차 포탑과 2차 포탑 사이를 계속 오감.

## 오브젝트 싸움 강제성 · 바론 가치 · 후퇴 반복 · 슈퍼스타

### 원인 (수정 전 코드 기준)
1. **오브젝트 싸움이 너무 자주·너무 쉽게 났다**
   - 오브젝트 처치·견제를 매 틱(5초) `ratioNear`(둥지 근처 전력비)만 보고 다시 정했다. 미리 "걸지 말지"를 정하는 단계가 없어서, 팀이 둥지 근처에 모이기만 하면 거의 항상 들어갔다.
   - 견제 여부(`contestMemo`)는 상대가 처치를 시작할 때 전력비로 한 번 굴렸지만, 골드·레벨·궁·점멸·조합·드래곤 스택·시야는 보지 않았다. 불리한 팀이 반대편을 미는 "교환"도 따로 없었다.
2. **바론 가치가 공성이 아니라 교전에 있었다**
   - 바론은 팀 골드 1,500을 한 번에 주고, 버프 3분 동안 교전 피해 +22%(`buffDps.baron`)를 줬다. 그래서 바론 뒤 싸움에서 거의 지지 않았다.
   - 공성 쪽 효과(미니언 강화·귀환 단축·포탑 피해)는 약하거나 없었다. 바론을 먹고도 골드 격차가 늘지 않거나, 반대로 교전으로 한 번에 끝났다.
   - 첫 바론을 먹는 팀은 이미 3천 골드 이상 앞선 경우가 대부분이었고, 6천 이상 앞서면 97~98% 이겼다.
3. **오브젝트 앞에서 진입·후퇴를 계속 바꿨다**
   - 계획을 매 틱 새로 골라 최소 유지 시간이 없었다. 진입·후퇴 기준도 같은 값(0.7)이라, 전력비가 그 근처에서 흔들리면 들어갔다 나갔다를 반복했다.
   - 견제 계획은 상대의 처치 진행이 잠깐 멈추면(둥지 안 교전) 무효가 되고, 수비 계획은 0.18 반경 경계에서 켜졌다 꺼졌다 했다.
   - 오브젝트 앞에서 크게 지고도(2명 이상 더 죽음) 후퇴로 세지 않아, 부활하면 같은 오브젝트에 다시 들어가 9분 넘게 같은 싸움을 반복한 경기도 있었다.
4. **슈퍼스타가 없었다**
   - 선수 능력치는 팀 티어 목표(S 83 / A 79.5 / B 76 / C 73) ± 4를 중심으로 `genStats(target, spread 6)`로 정규분포에서 뽑은 뒤, 모든 능력치를 같은 양만큼 밀어 목표 OVR에 맞췄다. 그래서 LCK 1군 OVR이 70~87에 몰렸고 90을 넘는 선수가 거의 없었다. 한 능력치만 튀는 선수도 없었다.
   - 잠재력은 `목표 + 나이별 난수`라 유망주가 스타로 크는 흐름이 없었다. AI 성장은 능력치마다 따로 굴려 잠재력에 닿으면 멈췄다.
