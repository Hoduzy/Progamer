# 챔피언 이미지가 이니셜로만 나오던 문제

증상: 밴픽 화면에서 애쉬·잔나·나미·밀리오·쓰레쉬·레오나·브라움·리 신 같은 챔피언이 이니셜(글자)로만 나오고, 같은 화면의 애니·니코는 정상. 아이패드 사파리.

## 1. 원인 확인

### 요청 URL은 정상이었다
- 밴픽 화면(1180×820, 크롬)에서 실패한 요청을 모두 찍어 봄 (`[img]` 콘솔 로그, 요청 실패 이벤트).
- 만들어진 주소는 전부 `https://ddragon.leagueoflegends.com/cdn/16.23.1/img/champion/<id>.png` 형태로, **버전이 undefined이거나 id가 빈 주소는 없었다.** 애쉬 `Ashe`, 잔나 `Janna`, 리 신 `LeeSin` 모두 champion.json의 id와 같다.
- 크롬에서는 117칸 모두 성공(실패 0). 즉 이름·주소 문제가 아니라 **요청이 실패했을 때의 처리** 문제.
- 실제 배포 주소를 검사하던 중에도 서비스 워커를 거친 요청 몇 개가 `net::ERR_FAILED`로 실패한 적이 있다(브라움·쓰레쉬·노틸러스·뽀삐·렉사이 — 모두 같은 시점에 한꺼번에 요청된 서포터 목록). 사파리에서 같은 일이 더 자주 생긴 것으로 본다.

### 실패를 영구히 굳히는 코드가 두 군데 있었다
1. **서비스 워커가 상태를 모르는 응답(opaque)까지 저장**: `<img>`가 CORS 없이 요청하면 서비스 워커는 응답 상태(200인지 오류인지)를 볼 수 없다. 기존 코드는 `res.ok || res.type === 'opaque'`이면 캐시에 넣었으므로, 한 번 잘못 받은 응답이 저장되면 **그 챔피언은 이후 계속 캐시의 깨진 응답을 받아 이니셜로 나왔다.** 특정 챔피언만 매번 안 뜨는 증상과 맞는다.
2. **`onerror`에서 바로 이니셜로 교체, 다시 시도 없음**: 요청이 한 번 실패하면 그 자리를 영구히 이니셜로 바꿨다.

### 한꺼번에 요청
- 밴픽 목록은 100칸이 넘는데 `loading="lazy"`만 걸고 동시 요청 수 제한이 없었다. 아이패드 사파리는 한꺼번에 많이 요청하면 일부를 실패시킨다.

### 순서 문제
- 앱 시작 때 Data Dragon 버전·champion.json을 기다린 뒤 첫 화면을 그리므로 순서 자체는 맞았다. 다만 이미지 주소를 **화면을 그리는 순간** 만들었기 때문에, 버전을 받기 전에 그려지는 경우가 생기면 주소가 잘못될 수 있는 구조였다.
- 이제 화면은 `<img class="lz" data-k="champ" data-id="Ashe">` 자리만 그리고, **주소는 이미지 로더가 Data Dragon 준비가 끝난 뒤(`setResolver`)에 만든다.** 준비 전에는 아무 요청도 보내지 않는다.

## 2. 수정

| 항목 | 내용 | 파일 |
|---|---|---|
| 다시 시도 | 실패하면 1초·3초·8초 뒤 최대 3번 다시 시도 (`CONFIG.ui.images.retryDelays`). 다시 시도할 때는 `?r=n`을 붙여 브라우저 메모리 캐시를 피함 | `js/ui/imgLoader.js` |
| 예비 서버 | Data Dragon 4번(처음 + 재시도 3번) 모두 실패하면 Community Dragon `…/champion-icons/<숫자 key>.png`에서 한 번 더. 숫자 key는 champion.json의 `key` (캐시에 `champKeys`로 저장, 예전 캐시에 없으면 champion.json을 다시 받음) | `js/ui/assets.js` |
| 이니셜 | 위가 모두 실패할 때만 이니셜. 실패 기록은 어디에도 저장하지 않으므로 화면을 다시 열면(새 `<img>`) 처음부터 다시 시도 | `imgLoader.js` |
| 동시 요청 | 동시에 최대 6개 (`CONFIG.ui.images.concurrency`). 같은 이미지를 여러 칸이 쓰면 요청 하나를 공유 | `imgLoader.js` |
| 보이는 칸 먼저 | IntersectionObserver로 화면에 들어온 칸부터, 스크롤하면 나머지. 보이는 칸은 미리 받기보다 앞에 줄 섬 | `imgLoader.js` |
| 미리 받기 | 게임 시작 화면에서 챔피언 아이콘 전체를 뒤에서 미리 받음. 오른쪽 아래에 "챔피언 아이콘 받는 중 23/117" 진행률 | `js/ui/screens/title.js` |
| 서비스 워커 | 이미지 요청을 CORS(`crossorigin="anonymous"`)로 바꿔 상태를 볼 수 있게 하고, **200 응답만 저장**. 캐시 이름을 `lckc-ddragon` → `lckc-img-v2`로 바꿔 예전 캐시(실패 응답이 섞였을 수 있음)를 지움. 서비스 워커 안의 자체 재시도는 없애고 화면 로더의 1·3·8초 재시도로 통일 | `sw.js` |
| localStorage | 실패 기록은 원래 저장하지 않았음 (`lckc.ddragon`에는 버전·이름·챔피언 목록만) | — |
| 로고 배경판 | 모든 팀 로고에 흰색 원형 배경판 `rgba(255,255,255,0.9)`, 안쪽 여백 = 크기의 12%. 로고는 전부 `teamLogo()` 하나로 그리므로 밴픽 상단·타이틀·허브·스코어보드·순위표·결과 화면 모두 적용 | `assets.js`, `css/style.css` |
| 디버그 패널 | 설정 → 디버그 모드를 켜면 왼쪽 아래 "🖼 이미지" 버튼 → 성공/재시도 중/실패 개수, 동시 요청 수, 재시도 중·실패 주소 목록 | `imgLoader.js` |
| 덤 | 밴픽 챔피언 칸에 상대 정보 줄이 있으면 칸이 늘어나지 않고 글자가 눌려 겹치던 문제 수정 | `css/style.css` |
